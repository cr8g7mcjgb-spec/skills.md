# suneung-coach — 수능 학습 코치 (모바일 전용)

2029학년도 수능을 준비하는 고1 학생용 Claude 스킬.
**학생이 휴대폰으로 쓰는 것**을 전제로 설계했다.

질문에 답하는 도우미가 아니라, 현재 수준을 진단하고 → 무너진 초·중등 기초를 찾아
→ 짧게 설명하고 → 수능 출제 방식으로 연결하고 → 문제를 내고 → 오답 원인을 분류하고
→ 복습을 예약하는 **파이프라인**이다.

---

## 설치 (학생이 하는 것)

### 1단계 — 스킬 업로드 (PC/웹에서 한 번만)

모바일 앱에서는 보통 스킬 **업로드**가 안 되고 **사용**만 된다.
그래서 처음 한 번은 컴퓨터나 웹 브라우저로 claude.ai에 접속해서 올린다.

1. `suneung-coach.zip`을 준비 (이 폴더를 압축한 것)
2. claude.ai 접속 → 설정 → **Capabilities / 기능** → **Skills**
3. 스킬 업로드 → zip 선택

> `[확인 필요]` 메뉴 이름과 위치는 앱 버전에 따라 다를 수 있다.
> Skills 항목이 안 보이면 2단계만으로도 대부분의 기능이 작동한다.

### 2단계 — 프로젝트 만들기 (이게 더 중요하다)

**기억을 담을 곳**이 필요하다. Claude 프로젝트를 쓴다.

1. 프로젝트 생성 → 이름 "수능"
2. **프로젝트 지침**에 `templates/프로젝트-지침.md` 내용 붙여넣기
3. **프로젝트 지식**에 `templates/상태블록.md` 추가

이후 학생은 **모바일 앱에서 그 프로젝트를 열고 대화**하면 된다.

### 왜 2단계가 필요한가

스킬은 "어떻게 가르칠지"를 정하지만, **학생의 상태를 기억하지는 못한다.**
모바일에는 파일이 없다. 그래서 프로젝트 지식에 든 **상태 블록**이 기억을 대신한다.

---

## 상태 블록 — 이 시스템의 심장

```
━━━ 수능 상태 ━━━
갱신: 2026-07-29

【성적】
국어 4 / 영어 4 / 수학 5

【확인된 결손】
· 중3 지수법칙 (음의 지수)
· 영어 관계사

【오답 카운터】
C 관계사 ⚠️4
M 조건누락 3

【복습 예정】
08-01 음의지수
08-05 관계사(리셋)

【다음 우선순위】
1. 관계사 (4회 누적)
2. 음의 지수 복구
━━━━━━━━━━━━━
```

**작동 방식**

```
공부 시작 → 상태 블록이 프로젝트 지식에 있음 → 코치가 읽고 시작
공부 끝   → 코치가 갱신된 블록 출력 → 학생이 복사 → 프로젝트 지식에 덮어쓰기
```

이걸 안 하면 매번 처음부터 시작한다. 스킬이 학생에게 저장을 계속 상기시킨다.

## 사용

프로젝트 안에서 그냥 물어보면 된다.

```
이 국어 지문 설명해주고
기초 5문제, 적용 5문제, 고난도 3문제 만들어줘
```

| 학생이 보내는 것 | 코치가 하는 것 |
| --- | --- |
| "이 지문 설명해줘" | 구조도 → 어휘 → 출제 포인트 → 문제 |
| "문제 만들어줘" | 기본/적용/고난도, 5개씩 끊어서 |
| "왜 틀렸어?" | 오답 코드 분류 → 결손 역추적 → 처방 |
| "오늘 뭐 해?" | 밀린 복습 확인 → 핵심 3개 |
| "이거 모르겠어" | 초·중등 역추적 → 바닥부터 재구축 |
| "수행평가 도와줘" | 평가표 분석 → 개요 (대필 안 함) |
| "저장" | 상태 블록 즉시 출력 |
| "더" | 심층 내용 다음 층 |
| "ㅇ" / "ㄴ" | 이해함 / 못 함 |

## 모바일 설계 결정

| 데스크톱이었다면 | 모바일이라서 |
| --- | --- |
| `<details>` 접기 | **"더" 명령** — 앱에서 접기가 안 된다 |
| 파이썬 복습 큐 스크립트 | **날짜 표 수동 계산** — 폰에 터미널이 없다 |
| `ERROR_LOG.md` 파일 | **상태 블록** — 폰에 파일이 없다 |
| 긴 답변 1개 | **15줄씩 분할 전송** |
| 6열 표 | **3열까지** — 화면에서 잘린다 |
| 가로로 긴 ASCII 도식 | **세로 30자 이내** |
| 학생이 문장으로 답변 | **"ㅇ" "1③ 2①" "더"** — 엄지로 친다 |

## 자료 조사

학생 계정에 네이버 MCP가 연결되어 있으면 수행평가·입시 조사에 쓴다.
사용 규칙은 `12-fact-verification.md`에 정의되어 있다.

- 정부·공공기관·연구소 → `naver_web_search`
- 뉴스 → `naver_news_search`
- 블로그·카페 → **5순위**. 핵심 사실의 유일한 근거로 쓰지 않는다
- 검색 결과 요약만 보고 답하지 않는다. `read_article`로 원문을 읽는다

---

## 설계 원칙

1. **결론 먼저, 15줄 이내.** 길면 나눠 보낸다
2. **빈 칭찬 금지.** "잘했어요" 대신 무엇이 맞고 틀렸는지
3. **정답 선공개 금지.** 학생 시도를 먼저 받는다
4. **기초를 뒤진다.** 고1 질문이 와도 초·중등 결손부터
5. **"왜?"를 붙인다.** 서울대는 암기가 아니라 사고를 본다
6. **사실/추정/확인 필요 구분.** 입시 정보를 출처 없이 단정하지 않는다
7. **기초와 수능을 동시에.** "기초부터 천천히"는 28개월 안에 목표에 못 간다
8. **모든 응답은 "지금 할 것" 하나로 끝난다**

## 한계

- **상태 블록을 저장하지 않으면 기억이 끊긴다.** 이 시스템의 가장 약한 고리다.
  스킬이 매번 상기시키지만, 결국 학생이 복사해야 한다
- `14-exam-system.md`의 입시 정보는 변경될 수 있다. 2029학년도 세부 시행계획과
  서울대 전형은 아직 미발표라 `[확인 필요]`로 표시해두었다
- 실제 기출문제를 재현하지 않는다. 기출은 EBS·평가원 자료로 별도 확보한다
- 수행평가 제출본을 대신 쓰지 않는다
- 모바일 앱의 스킬 업로드 지원 여부는 버전에 따라 다르다. 안 되면
  프로젝트 지침만으로도 핵심 동작은 유지된다
