# 13. 기출 코퍼스 구축 — "전수 분석"을 실제로 하려면

이 스킬은 기출 원문을 담고 있지 않다(`00-scope-and-limits.md`). 문항 단위 전수 분석을 하려면 원문을 확보해야 한다. 이 문서는 그 절차다.

## 1-B. 네이버 검색 도구로 찾기 — 실제 동작 검증됨

이 환경에는 네이버 검색 MCP 도구가 붙어 있다. 자료 탐색에 **먼저 이것을 쓴다.** 아래 내용은 실제로 호출해 확인한 결과다. `[검증: 2026-07 실측]`

### 사용 가능한 도구

| 도구 | 용도 |
|---|---|
| `naver_web_search` | 정부·공공기관, 학교, 연구소, 학술 자료. **공식 자료 찾을 때 1순위** |
| `naver_blog_search` | 회차별 총평·등급컷·오답률 정리 글 |
| `naver_news_search` | 시행계획, 출제 방향, 난이도 총평 보도 |
| `naver_cafe_search` | 입시 카페 공개글 |
| `read_article` | 위에서 얻은 URL의 본문 추출. **사이트 종류 무관** |

**호출 규약은 2단계다.** ① 검색 도구로 URL을 얻고 → ② `read_article`에 URL을 넣어 본문을 읽는다. 검색 결과의 제목·요약만 보고 판단하지 마라.

### 무엇이 되고 무엇이 안 되는가 — 실측 결과

| 대상 | 결과 | 비고 |
|---|---|---|
| 네이버 블로그 본문 | ✅ **전문 추출됨** | 등급컷 표, 오답률 상위 문항, 지문 소재까지 나온다 |
| 공공기관 게시판(교육청 등) | ✅ **목록·안내문 추출됨** | 자료실의 연도·학년·월별 게시물 목록을 그대로 읽을 수 있다 |
| 언론 기사 | ✅ 추출됨 | |
| 위키(ko.wikipedia) | ✅ 추출됨 | 연표 확인에 유용 |
| **PDF 파일(문제지 원문)** | ❌ **깨짐** | 바이너리가 그대로 나온다. 지문·선지 텍스트를 뽑을 수 없다 |
| 직접 다운로드(curl/wget) | ❌ 차단 | 프록시가 막는다 |
| 나무위키 | ❌ 403 | |

**결론**: 네이버 검색으로 **회차 정보·총평·등급컷·오답률·지문 소재·공식 안내문**까지는 확보된다. **문제지 원문 텍스트는 확보되지 않는다.**

### 원문 텍스트를 얻는 유일한 경로 — 검증 완료

> **사용자가 PDF 파일을 직접 대화에 올린다 → 로컬에서 텍스트를 추출한다.**

막히는 지점은 두 겹이다. ① 네이버 커넥터에 PDF 파서가 없다 ② 네트워크로 파일을 직접 받을 수 없다. 그러나 **파일이 로컬에 있으면 처리는 된다.** 실제로 확인했다. `[검증: 2026-07 실측]`

```
쪽별 텍스트 추출        ✅  pdfplumber
한글 정상 추출          ✅  왕복 검증 통과
원문자 선지 ①②③④⑤     ✅
배점 표기 [2점][3점]    ✅
낫표 「」, <보기> 상자   ✅
45문항 자동 분리        ✅  45/45 인식
```

**필요한 준비 (한 번만):**
```bash
pip install pypdf pdfplumber
# ImportError: No module named '_cffi_backend' 가 나면
pip install --upgrade cffi
```
pypi는 프록시 예외 목록에 있어 설치가 된다.

**추출 도구**: `scripts/pdf_extract.py`
```bash
python3 scripts/pdf_extract.py 문제지.pdf                 # 진단 + 미리보기
python3 scripts/pdf_extract.py 문제지.pdf --text out.txt  # 전체 텍스트
python3 scripts/pdf_extract.py 문제지.pdf --items out.csv # 문항 단위 CSV
```

문항 CSV에는 **번호·배점·`<보기>` 유무·선지 개수·발문 부정형 여부·발문**이 자동으로 채워진다. 여기에 `corpus_index.py`의 태깅 필드(골격, 오답 유형 등)를 이어 붙이면 된다.

**스캔 이미지 PDF는 안 된다.** 이 환경에 tesseract가 없어 OCR을 못 한다. 스크립트가 진단 단계에서 알려주므로, 그때는 텍스트 기반 원본(평가원 배포본)을 요청한다.

사용자가 "기출 다 있다"고 할 때, 링크가 아니라 **파일을 올려 달라고 요청**하는 것이 정확한 대응이다.

### 검증된 검색어 패턴

| 얻고 싶은 것 | 도구 | 검색어 예 |
|---|---|---|
| 공식 자료실 위치 | `naver_web_search` | `평가원 수능 기출문제 문제지 정답표 연도별` |
| 학평 자료실 | `naver_web_search` | `학력평가 자료실 교육청 정답표 정답해설` |
| 회차별 총평·오답률 | `naver_blog_search` | `[학년도] [회차] 국어 총평 등급컷 오답률` |
| 신설 체제 분석 | `naver_web_search` | `2028 예시문항 국어 분석 화법과 언어 독서와 작문` |
| 난이도 보도 | `naver_news_search` | `[학년도] 수능 국어 총평 출제 경향 평가원` |
| 시행계획 | `naver_web_search` | `[학년도] 수능 시행 기본계획 EBS 연계` |

### 자료 신뢰도 등급 — 반드시 구분해서 기록할 것

네이버로 긁은 자료는 **출처에 따라 신뢰도가 다르다.** 뭉뚱그리면 스킬의 `[검증]/[분석]` 규약이 무너진다.

| 등급 | 출처 | 표시 |
|---|---|---|
| 1급 | 평가원·교육부·교육청 **공식 문서·게시판** | `[검증]` |
| 2급 | 주요 언론 보도 | `[검증]` (단, 보도임을 밝힌다) |
| 3급 | 학원·강사 블로그, 입시업체 분석 | **`[확인필요]`** |

**3급 취급 주의사항** — 실측에서 확인된 문제들:
- **등급컷·오답률 수치는 출처마다 다르다.** 확정컷/추정컷 구분 없이 적힌 경우가 흔하다
- 블로그 글에는 **홍보 목적의 과장**이 섞인다
- 정형화된 문체·구성으로 보아 **자동 생성으로 의심되는 글**도 유통된다
- 따라서 3급 자료의 수치는 **그대로 옮기지 말고, 출처를 명시하고 `[확인필요]`로 표기**한다. 공식 자료로 교차 확인되면 그때 등급을 올린다

## 2. 저작권 유의

`[검증]` — 아래는 시·도교육청 학력평가자료실에 실제로 게시된 공식 고지다.

> 전국연합학력평가자료는 저작권자의 허락없이 문제의 일부 또는 전부를 복제, 배포, 출판, 전자출판하는 등의 일체의 행위를 금합니다.
> 학력평가자료에 탑재된 자료의 저작권은 시도교육청 또는 한국교육과정평가원에 있습니다.
> — 서울특별시교육청 학력평가자료실 안내문

이 고지는 학력평가에 대한 것이지만, 수능·모의평가 문항 역시 저작권이 평가원에 있다는 점은 같다.

`[검증]` 기본 사실 / `[분석]` 실무 판단

- 수능 문항의 저작권은 평가원에 있다
- 지문에 인용된 문학 작품·학술 저작은 별도 저작권자가 있다
- **개인·소규모 수업 목적의 이용**과 **복제·배포·판매**는 법적 취급이 다르다
- 이 스킬로 만든 자료를 **배포·판매할 계획이면 반드시 별도로 저작권 확인**을 거친다
- 안전한 방식: 자료에는 **출처 표기 + 해당 문항 번호**만 적고, 학생은 원본 PDF를 각자 열게 한다

산출물 원칙:
> 상업적 배포를 전제한 자료에는 기출 원문 전문을 싣지 않는다. 출처와 문항 번호로 지시한다.

**네이버로 긁은 자료에도 그대로 적용된다.** 블로그에 지문이 전재되어 있다고 해서 그것을 다시 옮겨도 되는 것은 아니다. 원 저작권자는 여전히 평가원과 각 작품 저작권자다.

## 4. 문항 단위 태깅 스키마

`[분석]` 코퍼스를 분석 가능한 데이터로 만들려면 문항마다 아래를 기록한다. CSV 또는 표.

| 필드 | 값 예시 | 비고 |
|---|---|---|
| `year` | 2026 | 학년도 |
| `sitting` | 수능 / 6월 / 9월 / 예시 | |
| `qno` | 12 | 문항 번호 |
| `area` | 독서 / 문학 / 화법 / 작문 / 언어 / 매체 | 매체는 2028 대비 시 제외 |
| `subarea` | 인문 / 사회 / 과학 / 기술 / 예술 / 융합 · 현대시 / 고전시가 / 현대소설 / 고전소설 / 극 / 수필 | |
| `set_id` | 2026-수능-S03 | 세트 식별자 |
| `passage_len` | 1620 | 지문 글자 수 |
| `skeleton` | E | 골격 A~H (`03-reading.md`) |
| `qtype` | 전개 / 일치 / 추론 / 보기적용 / 어휘 / 부분 | |
| `bogi` | Y / N | `<보기>` 유무 |
| `bogi_cat` | 사례형 / 수치형 / 주제해석형 … | `08-bogi-sources.md` |
| `points` | 3 | 배점 |
| `answer` | 4 | 정답 |
| `correct_rate` | 0.38 | 정답률 (EBSi 등) |
| `top_wrong` | 2 | 최다 선택 오답 |
| `wrong_tags` | 1:T4, 2:T6, 3:T1, 5:T8 | 선지별 오답 유형 |
| `work` | (문학) 작품명·작가 | |
| `notes` | | |

### 태깅 작업 순서

```
1) 세트 단위로 지문 유형·골격 판정
2) 문항별 유형·배점·정답 기록
3) 정답률 자료가 있으면 병합
4) 선지별 오답 태그 부여 ← 가장 오래 걸림. 문항당 5~10분
5) 검토: 같은 문항을 다른 날 다시 태깅해 일치하는지 확인
```

**현실적 규모**: 1회분(45문항) 태깅에 4~6시간. 9회분(2024~2026)이면 40~50시간. 이것이 "전수 분석"의 실제 비용이다. 이 숫자를 사용자에게 정직하게 말한다.

## 5. 분석 산출물 예시

코퍼스가 생기면 아래 분석이 가능해진다. 이것들이 "패턴 분석"과 "전수 분석"의 차이다.

| 분석 | 필요 필드 | 답할 수 있는 질문 |
|---|---|---|
| 제재별 출현 빈도 추이 | year, subarea | "과학 지문이 늘고 있나?" |
| 골격별 분포 | skeleton | "원칙-예외형이 몇 %인가?" |
| 오답 태그 빈도 | wrong_tags | "T6이 실제로 가장 어려운가?" |
| 정답률과 태그의 상관 | correct_rate, wrong_tags | "어떤 오답 유형이 가장 잘 속이나?" |
| 지문 길이 추이 | year, passage_len | "지문이 길어지고 있나?" |
| `<보기>` 비중 추이 | year, bogi | "`<보기>` 문항이 늘고 있나?" |
| 작품 재출제 | work | "어떤 작품이 반복되나?" |
| 배점 분포 | points, qtype | "3점은 어디에 붙나?" |

**이 표가 중요한 이유**: 사용자가 "전부 분석해 달라"고 할 때, 실제로 원하는 것은 대개 이 8개 중 몇 개다. 무엇을 알고 싶은지 먼저 좁히면 태깅 범위도 줄어든다.

## 6. 우선순위 있는 코퍼스 구축

`[분석]` 전량을 한 번에 하지 마라. 단계적으로.

| 단계 | 범위 | 소요 | 얻는 것 |
|---|---|---|---|
| 1 | 2028 예시문항 | 4시간 | 신체제 규격 |
| 2 | 2026 수능·6·9평 | 15시간 | 현행 기조 |
| 3 | 2024~2025 (6회) | 30시간 | 킬러 배제 이후 표본 |
| 4 | 2022~2023 (6회) | 30시간 | 공통+선택 체제 |
| 5 | 2017~2021 수능 (5회) | 25시간 | 고난도 표본 |
| 6 | 그 이전 | — | 문학 작품 목록만 추출해도 충분 |

**6단계는 전량 태깅하지 않는다.** 1994~2013 기출은 `work`(작품명) 필드만 뽑아 문학 DB를 만드는 것으로 충분하다. 이 판단은 `02-timeline.md`의 시대 구분에 근거한다.

## 7. 인덱싱 스크립트

`scripts/corpus_index.py` 사용:

```bash
python3 scripts/corpus_index.py corpus/           # 인덱스 생성
python3 scripts/corpus_index.py corpus/ --check   # 누락 확인
python3 scripts/corpus_index.py corpus/ --template 2026 수능  # 태깅 CSV 생성
```

기능:
- 폴더를 훑어 확보/미확보 회차를 표로 출력
- 태깅용 CSV 템플릿 생성(문항 수만큼 행 생성)
- 태깅 CSV의 필드 값 유효성 검사

## 8. 코퍼스 없이 요청을 받았을 때

사용자가 "전 기출 분석"을 요구했는데 코퍼스가 없으면, **순서가 정해져 있다.**

```
1) 네이버 검색부터 돌린다 (§1-B)
   → 회차 정보·총평·오답률 상위 문항·지문 소재·공식 안내문은 여기서 확보된다
   → 이것만으로도 '어떤 제재가 언제 나왔나' 수준의 지도는 그릴 수 있다

2) 그래도 안 되는 것을 정확히 말한다
   → 지문·선지 원문 텍스트. PDF가 깨져서 못 읽는다

3) 사용자에게 PDF 파일 업로드를 요청한다
   → 링크를 달라고 하지 마라. 파일을 올려 달라고 해야 한다
   → 올라오면 pdf 스킬로 텍스트를 뽑아 태깅에 들어간다

4) 원하는 분석이 §5의 어느 항목인지 좁힌다 — 대개 전량이 필요 없다
```

**1번을 건너뛰고 "자료가 없습니다"라고 답하지 마라.** 네이버 경로로 확보되는 것이 생각보다 많다.

말하는 방식:

> 네이버 검색으로 회차별 총평·등급컷·오답률 상위 문항·지문 소재까지는 확보했습니다.
> 다만 지문과 선지 **원문 텍스트**는 PDF가 열리지 않아 못 가져옵니다.
> 문항 단위 전수 통계가 필요하시면 **문제지 PDF를 이 대화에 올려 주세요.**
> 올려 주시면 텍스트를 추출해 태깅에 들어가겠습니다.
> (2024~2026 9회분 기준 태깅에 약 40~50시간 규모의 작업입니다.)

### 확보 수준별로 할 수 있는 분석

| 확보 수준 | 가능한 분석 |
|---|---|
| 아무것도 없음 | 출제 문법 체계(이 스킬의 references) |
| **네이버 검색만** | 회차별 총평, 제재·소재 지도, 오답률 상위 문항 목록, 체제 변화 연표 |
| **+ PDF 원문** | 문항 단위 전수 태깅, 오답 유형 분포, 지문 길이 추이, 골격 분포, 작품 재출제 통계 |
